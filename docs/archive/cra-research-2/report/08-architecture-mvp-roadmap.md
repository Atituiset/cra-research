## 1. 参考架构（逻辑五层 + 关键决策）

```
┌─ L5 接入与交付 ───────────────────────────────────────────┐
│ CI(Webhook/门禁) │ 文件(SBOM/CSV上传, 导出zip) │ API/门户 │ MCP Server(Phase1) │
├─ L4 应用服务 ────────────────────────────────────────────┤
│ 产品台账(版本/支持期) │ 告警流 │ VEX工作台 │ 事件状态机 │ 合规中心 │ 客户应答包 │
├─ L3 判定引擎 ────────────────────────────────────────────┤
│ 多源归一(别名/区间/backport) │ Reachability(L1/L2[+L4可选]) │ │
│ Exploitability证据卡(四轴) │ VEX状态机+理由词表 │ 修复建议(四选) │ Agent编排(A1/A2) │
├─ L2 证据与图 ────────────────────────────────────────────┤
│ Evidence Graph(06 §4.2 schema, 版本化快照, 10年留存设计) │ 序列化适配(SBOM/VEX/CSAF/报告) │
├─ L1 数据源 ─────────────────────────────────────────────┤
│ NVD(降级意识)/OSV/GHSA/厂商CSAF-adv │ KEV │ EPSS │ CVSS-v4 │ 代码仓库/registry │ 标准格式适配层 │
└──────────────────────────────────────────────────────────┘
横切：多租户与数据域 ｜ RBAC+审批 ｜ 审计日志 ｜ 策略引擎(SLA/阈值) ｜ Agent会话观测
```

**四个架构决策（Day 1 锁定，防 03 §5 迁移悲剧）**
1. **实体模型产品级**：Product→Release→Component 引用，alert/判定/事件全部挂 Release——不是仓库级 alert 表。
2. **图即真源**：L3 引擎写图，L4 应用读图；**任何判定/报告/导出必须能回指 snapshot ID**（06 §4.2）。
3. **标准适配层收口在 L2 序列化 + L1 情报归一**：格式/数据源变化不进业务逻辑（02 §5 的 implementing acts 风险对策）。
4. **Agent 无特权默认**（06 §3：A1 草稿、A2 白名单、工具 MCP 化、审批钩子在 L4）。

## 3. 3-5 个 PoC（mvp.md #20 核心交付：每个含假设/做法/验证标准）

### PoC-1 · 多源情报关联引擎（风险最低，先赢）
- **假设**：在 NVD risk-based 收缩后，多源归一+区间置信度展示能把"匹配争议"从工单变成可解释证据。
- **做法**：取 200 个真实 CVE（跨 Java/Go/npm + Debian/Ubuntu backport 案例），实现别名消解（NVD↔OSV↔GHSA）、区间对齐、backport 状态读取（发行版 advisory），输出 `match-explain.json`（五层各层结论+来源 URL+置信度）。
- **验证标准**：
  1. 区间冲突案例 100% 能给出**可解释差异**（而非静默择一）；
  2. 人工金标集（50 条专家标注受影响/不受影响）准确率 ≥90%；
  3. 单次全量重算（200 CVE × 500 组件）< 5 分钟。
- **产出**：D2 域引擎原型 + 本报告 03 §2 缺陷 1/2 的实测数据（替掉"基于公开资料"）。

### PoC-2 · 函数级 Reachability 原型（05 §7 已给验收标准）
- **假设**：L2 call path 证据质量足以支撑 VEX `not_affected` 举证，且 Java/Go 两语言可达。
- **做法**：见 05 §7——10 个人工注入样本（真可达/真不可达各半）+ 可视化 path 导出。
- **验证标准**：05 §7 四条（≥9/10 不可达识别、≥8/10 可达召回、单仓<10min、evidence.json 符合 05 §5 字段）。
- **对照**：抽样对比 Endor/Oligo 公开案例的证据展示形态（不比降噪百分比）。

### PoC-3 · VEX 判定工作流闭环（主差异化验证）
- **假设**：把 VEX 从"导出格式"做成"状态机+强制证据+SLA"，设计伙伴愿意为此付费意愿外的持续使用。
- **做法**：最小链路 = PoC-1 的告警 →（可选 PoC-2 证据）→ 判定面板（04 J2 UI）→ 状态迁移强制挂证据 → 导出 CDX VEX + CSAF VEX 两种格式；investigating 超时升级规则可配。
- **验证标准**：
  1. 导出的 VEX 通过公开 validator（CycloneDX/CSAF schema 校验器）100% 合法；
  2. 每条状态变更在图里可回放（snapshot ID 查询 <1s）；
  3. **≥3 家设计伙伴连续 4 周使用 J2**（留存>功能炫技）；
  4. 对照组：同批漏洞用"清单式工具"人工判定耗时 vs J2 耗时（目标 ≥3× 提速，补 03 §3.1 痛点 2 数据）。

### PoC-4（可选并行）· 事件报告状态机（若 Phase 0 需销售素材则提前）
- **假设**：24h 预警预填+倒计时是采购会议里最有冲击力的演示（04 J3）。
- **做法**：纯流程+字段（不接真 SRP 提交）：KEV 命中→建 Incident→冻结 SBOM 快照→按 Art.14 条目生成三份草稿→人工审批→导出。
- **验证标准**：
  1. 与 EUR-Lex Art.14 条目逐字段对照表评审通过（法务/合规顾问背书）；
  2. 桌面推演：从"KEV 新增"到"24h 草稿完成" < 30 分钟（对比现状数天）；
  3. 快照冻结可复现（同一 Incident 重开导出 byte-identical）。

### PoC-5（远期/时间盒 2 周）· Agent 修复草稿
- **假设**：在我们自己的仓库上，A1 agent 对"明确 fix version 存在"的升级类告警能产出可合并 PR 且证据附言正确。
- **做法**：06 §3 九问的最小实现（工具白名单、审批钩子、会话日志落图）。
- **验证标准**：20 条告警 → PR 采纳率 ≥50%、零越权工具调用、每 PR 含 CVE+SBOM diff+复扫三件套证据。**不达标不阻塞主线**（此能力已商品化，见 07 §3）。
